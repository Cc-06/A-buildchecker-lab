# ADR-A17-001：A 组图接入、版本身份与缓存失效

日期：2026-11-16；成员：陈佶哲，241880606；组号：A17。状态：已在本人服务器验证。

## 问题

BuildChecker 图与 EChecker 缓存格式不同；基线与目标报告可能混用，运行 PID 差异不应影响发现比较。A/B 传输还需要内容完整性和提交约束。

## 决策

沿用共享编排器和版本化 envelope，保留原始组件报告。实际图投影到 main.o/helper.o，先核对 GCC 基线，再写入缓存。目标增量与同目标真实全量比较 (type,target,dependency) 集合。

外层 envelope=e11e12-1，包含 kind、commit、status、job_id、trace_id、data 和 artifact URI/SHA256。基线 full-check 属于 base，增量属于 target。组件内部追踪 ID 可以独立存在。

继续采用全局 key 保守失效：函数体单独变化可复用观察，预处理指令/文件集合/recipe/参数/编译器变化刷新全部对象。当前不引入未经验证的按对象失效。

## 备选与取舍

只传原始 JSON 缺少统一消费边界；四个独立服务增加部署和协调成本。当前方案复用课程实现，明确提交和产物身份。代价是当前双对象接口和保守失效限制了泛化与性能；接入其他项目需适配并测试。

## 验证

本人服务器完成 15 项契约测试、include 与函数体变化两轮真实 strace/GCC 全量-增量对照、自主提交及 STALE_REPORT。A 侧 HTTP 的幂等202、冲突409、错误输入400、路径越界404和85个产物内容校验通过。详细 SHA/job/trace 见个人报告与实测摘要。

生成样例不计为真实维护项目；真实项目接入和完整 B/E12 修复链分别记录验收。
